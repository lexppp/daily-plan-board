# 每日计划台 · Daily Plan Board

一个**单文件、零依赖、可离线**的个人计划管理应用。设定目标、定时提醒、每日打卡、周计划排期，全部数据存在你自己的浏览器里，不上传任何服务器。

> 整个应用就一个 `index.html` 文件。下载它，双击打开，就能用。

---

## ✨ 功能一览

| 功能 | 说明 |
| --- | --- |
| **四种计划周期** | 单日 / 一周 / 一个月 / 长期，自由切换 |
| **优先级管理** | P0 紧急重要、P1 重要、P2 一般，左侧色条一眼区分 |
| **每日打卡** | 周期任务按天打卡，第二天自动重置，不影响整体进度 |
| **周计划板** | 周一至周日 7 列看板，可提前排计划，也能提前完成 |
| **定时提醒** | 自定义提醒时间，到点响铃 + 桌面通知 |
| **数据看板** | 完成率环形图、近 7 天柱状图、全年热力图、连续打卡天数 |
| **跨设备同步** | 生成同步码 → 另一台设备粘贴 → 自动合并，无需服务器 |
| **导入导出** | JSON 备份/恢复，防止数据丢失 |
| **手机适配** | 响应式布局，可添加到手机桌面像 App 一样使用 |
| **完全离线** | 无 CDN、无框架、无后端，断网照常使用 |

## 🚀 三种使用方式

### 方式一：下载即用（推荐新手）

1. 点击仓库右上角 **Code → Download ZIP**，或只下载 [`index.html`](./index.html)
2. 解压后 **双击 `index.html`**
3. 开始添加你的第一条计划

就这么简单。不需要安装 Node、不需要装环境、不需要联网。

### 方式二：在线直接使用

把 `index.html` 拖进任意浏览器即可，或访问作者部署的在线版本。

### 方式三：部署到 GitHub Pages（让别人也能访问）

1. Fork 本仓库
2. 进入 **Settings → Pages**
3. Source 选择 `Deploy from a branch`，Branch 选 `main`，目录选 `/ (root)`
4. 保存后等待 1–2 分钟，访问 `https://<你的用户名>.github.io/daily-plan-board/`

## 📖 使用说明

### 添加计划
点击「+ 添加计划」，填写标题、选择优先级与周期、设定日期与提醒时间即可。

### 周计划板（提前排期）
顶部切换到 **周计划** 标签页：

- 每列底部「+ 添加」可在任意一天录入计划，回车可连续添加
- 未来某天的计划可以直接勾选 → 提示「✓ 提前完成！」
- 未来计划**不会**污染「今天要处理」，也**不会**被算作逾期
- `←` `→` 可翻看上周 / 下周，点「回到本周」一键归位
- 颜色含义：蓝框 = 今天，红底 = 过去未完成，灰划线 = 已完成

### 每日打卡
周期任务（一周 / 一个月 / 长期）在列表里会显示 `x/y 天` 进度。每天完成后点一次勾选，第二天自动重置为待完成。

### 定时提醒
1. 点击顶栏「提醒」按钮，开启开关并设定时间
2. **首次使用必须授权浏览器通知权限**（地址栏左侧的小锁图标里开启）
3. 提醒触发时会播放提示音并弹出桌面通知

### 跨设备同步
数据存在各自设备的浏览器本地，天然不互通。需要同步时：

1. A 设备点击「同步」→ 生成同步码 → 复制
2. 通过微信文件传输助手等方式发到 B 设备
3. B 设备点击「同步」→ 粘贴同步码 → 合并

合并按 `id` 去重，同一条计划保留**更新时间较新**的版本，不会互相覆盖丢失。

## ⚠️ 手机使用注意事项

### 添加到桌面（像 App 一样打开）
- **Android / 三星**：Chrome 打开链接 → 右上角菜单 →「添加到主屏幕」
- **iPhone**：Safari 打开链接 → 底部分享按钮 →「添加到主屏幕」

### 后台不提醒怎么办？（重点）
浏览器被系统杀掉后台后，页面的计时器会停止，提醒自然不会响。这是手机系统的省电策略，不是应用故障。解决办法：

| 平台 | 操作 |
| --- | --- |
| **三星** | 设置 → 电池 → 后台使用限制 → 把浏览器加入「永不休眠的应用」；设置 → 应用程序 → 浏览器 → 电池 → 选「不受限制」 |
| **小米 / 红米** | 设置 → 应用设置 → 应用管理 → 浏览器 → 省电策略 → 选「无限制」；多任务界面长按该页面加锁 |
| **华为** | 手机管家 → 应用启动管理 → 浏览器 → 手动管理，三项全部打开 |
| **iPhone** | 无解（iOS 会冻结后台网页），建议依赖提醒通知或改用日历提醒 |

此外，应用内已做兜底处理：提醒触发记录持久化保存，页面**切回前台时会立即补检**，漏掉的提醒会补上。页面顶部也有黄色提示条，建议保持页面在后台挂着。

## 🔒 数据存在哪？

全部存在浏览器的 `localStorage` 里，共三个键：

| 键名 | 内容 |
| --- | --- |
| `wb_dailyplan_tasks` | 所有计划数据 |
| `wb_dailyplan_reminder` | 提醒设置 |
| `wb_dailyplan_fired` | 已触发提醒记录（防止重复打扰） |

**这意味着：**
- ✅ 数据不上传任何服务器，完全私有
- ✅ 断网也能正常使用
- ⚠️ 清理浏览器数据 / 换浏览器 / 换设备，数据不会自动跟随
- ⚠️ 建议定期用「导出 JSON」备份

## 🛠 技术说明

- **纯原生实现**：HTML + CSS + 原生 JavaScript，无任何框架与 CDN 外链
- **单文件架构**：样式与脚本全部内联，一个文件即完整应用
- **手绘图表**：进度环、柱状图、热力图均由原生 SVG 绘制，不引入图表库
- **提醒机制**：Web Audio API 生成提示音 + Notification API 桌面通知 + 持久化补检
- **响应式**：桌面端多列栅格，`<900px` 自动切换为单列堆叠

## ❓ 常见问题

**这个应用会失效吗？**
不会。它是纯静态 HTML 文件，不依赖任何服务器。只要文件还在，十年后打开照样能用。

**需要联网吗？**
不需要。首次下载后完全离线可用。

**别人能用我的数据吗？**
不能。数据只存在各自的浏览器本地，互不干扰。

**周计划完成后第二天会重置吗？**
会。周期任务按天打卡，第二天自动回到待完成状态，历史打卡记录保留在热力图里。

**逾期任务无法打卡？**
已修复。周期任务在周期结束后仍可补打卡，打卡后即不再标记为逾期。

**能改成微信小程序吗？**
不能直接改。小程序是另一套代码体系（WXML/WXSS + `app.json`，不是 HTML/DOM），需要用微信开发者工具重新开发。本应用可作为功能参考。
